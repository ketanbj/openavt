# Contribute to OpenAVT

Start with the [documentation map](docs/README.md), [code map](docs/code-map.md)
and [development guide](docs/development.md). Coding agents should also read
[AGENTS.md](AGENTS.md).

1. Locate the source module and closest behavior tests before changing code.
2. Preserve separate transport identity, customer authority and ordinary speech.
   Describe changed guarantees/assumptions in the corresponding guide and tests.
3. Use `make check-docs` for documentation-only work. Use the development guide's
   focused checks for protocol, CLI, packaging or evidence changes.
4. Keep historical measurements and proposed results distinct. New exploratory
   runs go in ignored `output/`; publication copies require matching review/hashes.
5. Keep optional integrations separate from core/SDK imports. Include dependency
   changes in `uv.lock` and preserve the version generated by setuptools-scm.

Keys, credentials, customer grants, databases and unconsented recordings are not
committed. Code is Apache-2.0; redistributed media/data need documented rights.
Actual package releases follow a separate workflow described in the release guide.
